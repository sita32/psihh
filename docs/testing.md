## 1. Подход

Сервер проверяется автоматическими тестами четырёх видов:

| Вид | Что проверяется | Как |
|---|---|---|
| Модульные | отдельные функции без базы и сети | функции вызываются напрямую |
| Интеграционные (API) | весь путь запроса: маршрут → сервис → репозиторий → PostgreSQL и Redis | HTTP-запросы к приложению через supertest, без открытия порта |
| Правила базы данных | триггеры и ограничения `schema.sql` – действуют даже при ошибке в коде сервера | SQL-запросы напрямую, каждый тест в транзакции с откатом |
| Реальное время | доставка сообщений чата через Socket.IO | сервер на свободном порту, клиент socket.io-client с cookie входа |

Приёмы, которые делают тесты надёжными:

- **Изоляция.** Перед каждым прогоном тестовая база `ryadom_test` создаётся заново из `schema.sql`, `seed.sql` и `demo.sql`, Redis работает в отдельной базе (№ 1). Данные сайта не затрагиваются; на базе без суффикса `_test` тесты не запускаются.
- **Свои данные.** Тесты регистрируют своих пользователей и проводят своего психолога через весь путь: анкета → диплом → заявка → одобрение модератора → публикация → окна расписания. Поэтому тесты не зависят от демо-данных и друг от друга.
- **Проверка свойств, а не конкретных значений.** Например, «у каждого найденного по фильтру есть метод КПТ» вместо «найдено 6». Свободные окна в демо-данных считаются от дня загрузки – тесты не устаревают со временем.
- **Время.** Правила, зависящие от начала встречи (отметка «состоялась», запрет отмены после начала), проверяются сдвигом окна записи в прошлое прямо в тестовой базе.
- **Ограничения попыток.** Сервер ограничивает вход и регистрацию по IP; каждый тестовый «браузер» ходит со своего адреса (заголовок `X-Forwarded-For`, сервер работает за nginx).

## 6. Проверка самих тестов

Чтобы убедиться, что тесты действительно обнаруживают ошибки, в код намеренно вносились неисправности (мутационная проверка). После каждой проверки исходный код возвращался.

| Где | Внесённая ошибка | Результат |
|---|---|---|
| `services/matching.service.js` | Подбор перестаёт учитывать формат консультации | matching.test.js: «близкие варианты» – упал |
